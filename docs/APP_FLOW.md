# App Flow — FinalWeek（求职版 MVP）

## Screens

| Route | 页面 | 职责 |
|---|---|---|
| `/` | 落地页 | 简要介绍项目并进入登录 |
| `/login` | 邮箱登录 | 请求并验证邮箱验证码 |
| `/courses` | 课程列表 | 创建、查看、重命名和删除课程 |
| `/courses/:id/materials` | 课程资料 | 上传资料、查看上传/解析状态、重试失败任务 |
| `/courses/:id/outline` | 知识提纲 | 生成树状提纲、查看来源、调整重要度 |
| `/courses/:id/plan` | 复习计划 | 填写计划输入、生成每日任务、勾选完成 |
| `/courses/:id/chat` | 课程问答 | 文字提问、查看课程引用和聊天历史 |
| `/settings` | 账号设置 | 查看邮箱、退出登录 |

首版重点适配 Chrome/Edge 桌面浏览器，并保证手机浏览器基本可用；不做完整浏览器兼容矩阵。

## Flow 1 — 登录与创建课程

1. 用户输入邮箱，请求验证码。
2. 系统执行邮箱格式和 Redis 限流校验，通过 Mailpit/SMTP 发送验证码。
3. 用户提交验证码，验证成功后创建 HttpOnly Cookie Session。
4. 用户进入课程列表；空状态显示“创建第一门课程”。
5. 用户输入课程名称并创建课程。
6. 系统返回课程详情，默认进入资料页。

### Failure States

- 验证码错误或过期：提示重新输入或发送，不清空邮箱。
- 请求过于频繁：返回 429 和剩余等待时间。
- Redis 不可用：登录及所有需要认证的后端请求统一返回 HTTP 503；静态落地页和健康检查仍可访问。
- 已有 8 门课程：禁止继续创建，提示删除不用的课程。
- 越权访问课程 ID：返回统一的无权访问/不存在响应，不泄露课程信息。

## Flow 2 — 分片上传资料

1. 用户选择 PDF、PPTX、TXT/MD、MP3 或 MP4，并选择资料类型、填写可选重点说明。
2. 前端校验扩展名和大小，调用初始化接口获取 `uploadId`、分片大小和总分片数。
3. 前端并发上传固定大小分片；每个成功分片先落 MinIO，再记录到 Redis Set。
4. 页面刷新或网络恢复后，前端通过 `uploadId` 查询已完成分片并上传差集。
5. 所有分片成功后，前端主动调用 complete。
6. 后端获取该上传任务的合并锁，检查归属、分片完整性和 completed 标记。
7. 后端按序合并分片，计算完整文件哈希，校验类型并保存最终 MinIO 对象与资料记录。
8. 若同一课程已有相同哈希的资料，返回已有资料并清理本次临时文件。
9. 后端先创建 `PENDING_PUBLISH` 解析任务并执行 RabbitMQ 用户级/全局限流：通过后投递消息，publisher confirm 成功后进入 `QUEUED`；限流、发布或 confirm 失败均条件进入 `PUBLISH_FAILED` 并记录具体错误。限流失败不回滚已成功的上传，接口返回同一资料和任务且不发送消息，用户稍后重新投递。

### Failure States

- 单个分片失败：其他分片保留，只重传失败分片。
- complete 重复调用：返回同一资料和任务，不重复合并。
- 两个 complete 并发：只有获取锁的请求执行，另一请求等待或返回处理中。
- 上传元数据过期：提示重新初始化；定时任务清理过期 Redis 状态和 MinIO 临时分片。
- 文件损坏、伪造类型或超限：拒绝创建解析任务，显示具体原因。
- 已解析成功资料：首版不显示单独删除操作；用户只能删除整门课程。待投递、投递失败、排队、失败或已取消资料可删除；排队资料先原子取消。处理中/重试中资料暂不可删除。

## Flow 3 — RabbitMQ 异步解析

1. Spring Boot 在 MySQL 写入 `PENDING_PUBLISH` 任务后投递 RabbitMQ。
2. publisher confirm 成功时任务变为 `QUEUED`；失败时变为 `PUBLISH_FAILED`。接口返回 202 和 `taskId`，不等待解析完成。
3. 消费者收到消息，基于任务业务键获取 Redisson 锁并检查任务终态；为处理消息早于 confirm 状态回写或在 confirm 超时后延迟到达的竞态，消费者允许将 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 或 `RETRYING` 以 CAS 推进为 `PROCESSING`。confirm 回调不得把 `PROCESSING` 等后续状态倒退为 `QUEUED`。
4. 若任务已成功，直接确认消息；若未完成，从最近成功 checkpoint 继续。
5. 消费者依次推进：内容提取 → 分块 → Embedding → 索引 → 完成。
6. 每完成一个阶段就更新 MySQL checkpoint，并通过 Redis/SSE 推送进度。
7. 单次外部调用默认最多 3 次执行（首次 + 2 次重试）；整个任务默认最多 3 次执行（首次消费 + 2 次重投），两类计数分别记录。
8. 达到任务级最大执行次数后写失败任务表/失败队列，状态为 `FAILED`。

### SSE Recovery

- SSE 只是通知渠道，不是业务真相。
- 断线重连后前端先查询任务状态，再继续订阅。
- 即使中间事件丢失，用户仍能获取 MySQL 中的最终状态。

### User Actions

- `PENDING_PUBLISH`、`QUEUED`：允许取消；`PUBLISH_FAILED`：允许取消或重新投递。重新投递复用同一任务和执行轮次，先限流，再以 CAS 回到 `PENDING_PUBLISH` 后发布；若原消息此时延迟到达并抢占成功，重新投递返回冲突且不再发送第二条消息。
- `PROCESSING` / `RETRYING`：只允许查看阶段和错误摘要。
- `FAILED`：允许手动重试或删除资料。手动重试复用原 `taskId` 和 checkpoint，重置新一轮任务级投递预算并增加手动重试轮次，不新建第二条解析任务。
- `SUCCEEDED`：允许查看解析摘要、生成提纲和开始问答。

取消、重新投递与消费并发时，以 MySQL compare-and-set 为准：只有未开始任务能改为 `CANCELLED`；消费者启动前必须将 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 或 `RETRYING` 原子改为 `PROCESSING`，拿到已取消任务时直接 ack。confirm 超时后延迟到达的原消息与用户重新投递只能有一方成功推进状态。

## Flow 4 — 不同资料的解析

### PDF / PPTX / TXT

1. 提取原生文字。
2. PDF 扫描页或 PPT 渲染页文字不足时调用 OCR。
3. 保存页码、幻灯片号或段落号。
4. 规范化并生成 `CourseSegment`。

### MP3 / MP4

1. FFmpeg 检查时长与媒体格式。
2. 提取音轨并按固定时长切分，通过支持本地文件/音频流的 `paraformer-realtime-v2` Java 接口调用 ASR 获取时间戳文本；不依赖百炼从公网 URL 回源本地 MinIO。
3. MP4 同时按场景变化和保底间隔抽取关键帧，感知哈希去重后调用 OCR。
4. 将 ASR 和 OCR 按时间范围合并成 `CourseSegment`。
5. ASR 或 OCR 单路部分失败时保留另一条可用内容并显示警告；两路都无有效内容时解析失败。

## Flow 5 — 构建课程知识库

1. 将课程片段按语义边界和最大长度切成 chunk。
2. 保存 chunk 原文、来源定位和课程归属。
3. 调用百炼 Embedding，并写入 Qdrant。
4. Qdrant point 携带用户、课程、资料和片段标识。
5. 全部 chunk 写入 Qdrant；Lucene 写入在课程级 Redisson 锁 `lucene-index:{courseId}` 内，使用确定性 document ID 对本资料 chunk 做增量 bulk upsert 并 commit。完成后标记 `EMBEDDING_COMPLETED`。
6. 资料解析任务随后原子进入 `COMPLETED`、任务/资料状态进入 `SUCCEEDED`，此时资料才进入可检索状态；是否生成提纲不影响资料解析完成。从 MySQL 全量重建 Lucene 仅用于初始化或故障修复。

### Failure States

- 部分 Embedding 调用失败：任务按重试规则执行；仍失败则整个 Embedding 阶段失败，不发布半完成索引。
- Qdrant 重复 upsert：使用确定性 point ID 覆盖同一 chunk，不生成重复记录。
- Qdrant 不可用：提纲和问答暂不可用，文本解析结果保留，重试时从 Embedding 阶段继续。

## Flow 6 — 混合检索

1. 用户问题或提纲生成目标进入检索服务。
2. 向量分支：问题 Embedding 后在 Qdrant 中按 `userId + courseId` 过滤并召回 TopK。
3. 关键词分支：从当前课程片段建立/读取轻量 BM25 索引并召回 TopK。
4. 使用 RRF 根据两路排名融合，去重后选择最终上下文；RRF 常数和 TopK 均为可配置首版默认值。
5. 上下文附带原资料位置，交给提纲或问答生成器。

若某一路临时不可用，可使用另一路降级并在日志记录；两路都不可用则明确失败，不让模型脱离课程资料生成资料型回答。

## Flow 7 — 生成知识提纲

1. 至少一份资料完成索引后，“生成提纲”可用。
2. 若已有提纲，弹窗提示新结果会覆盖当前提纲。
3. 用户确认后先执行 RabbitMQ 用户级/全局限流；未通过则返回 429 且不创建任务，通过后创建异步提纲任务。
4. 若本课程已有活动提纲任务，返回该任务而不重复创建；同一课程同时最多有一个活动提纲任务。
5. 系统检索课程片段，并将学生重点说明、教师强调语句、真题/题库类型作为重要度信号。
6. 大模型返回固定 JSON 树结构；后端校验层级、重要度和来源是否有效。
7. 校验通过后按生成请求版本 CAS 原子替换当前提纲；失败时保留旧提纲，旧任务不得覆盖较新请求的结果。
8. 用户可把知识点的重要度改为高/中/低。
9. 用户点击来源，在资料预览中定位页码、幻灯片、段落或视频时间点。

提纲生成拥有独立 checkpoint：`CONTEXT_RETRIEVED → OUTLINE_GENERATED → COMPLETED`，不写入资料解析 checkpoint。来源跳转时，前端先获取经过权限校验的预览描述和短期 URL；PDF/PPTX 使用规范化 PDF 预览，MP3/MP4 播放器通过 Range 请求加载并设置 `currentTime`。

### Failure States

- JSON 格式错误：只做一次严格结构修复，仍失败则任务失败。
- 知识点没有有效来源：不发布该次结果。
- 已有提纲生成新版本失败：当前提纲保持不变。
- 首版不处理人工重要度与重新生成结果的合并；覆盖确认后人工修改会被替换。

## Flow 8 — 简单每日复习计划

1. 用户进入计划页；没有提纲时引导先生成提纲。
2. 用户填写考试日期、每日可用分钟数、整体掌握程度和目标成绩。
3. 前端携带请求幂等键通过同步 REST 提交，系统先执行用户级计划生成限流，再按知识点重要度和剩余日期生成每日任务；首版不进入 RabbitMQ、不使用任务 SSE。
4. 任务显示日期、知识点、预计分钟数和完成框。
5. 用户手动勾选完成或撤销。
6. 再次生成时提示会覆盖当前计划；确认后替换。

### Failure States

- 考试日期已过、每日时间为零：表单内阻止提交。
- 生成失败：保留当前计划。
- 请求超过可配置同步超时：返回明确超时错误，保留当前计划；客户端先重新读取当前计划，再以同一幂等键重试，服务端不得产生多份当前计划。
- 首版不自动识别逾期、不重排、不提供复杂编辑。

## Flow 9 — 课程文字问答

1. 用户进入课程问答，输入文字问题。
2. 前端通过非流式同步 REST 提交；系统执行用户级 Redis 限流。
3. 系统在当前课程执行混合检索。
4. 大模型根据检索上下文生成回答，并返回使用的 segment ID。
5. 后端校验引用属于本用户、本课程且确实被提供给模型。
6. 前端展示回答和来源按钮。
7. 若课程资料不足，可追加明确标记的“通用知识补充”。
8. 问答按课程保存为一条连续历史。

### Failure States

- 触发限流：返回 429 和稍后重试提示，不投递模型请求。
- 没有检索结果：说明资料不足，不伪造来源。
- 模型调用失败：保留用户问题并显示重试按钮。
- 引用校验失败：整条助手回答不保存，按结构错误处理。
- 请求超过可配置同步超时：将用户消息标为失败并允许重试；首版不切换到 SSE 流式回答。

## Flow 10 — 课程删除

1. 用户确认删除课程。
2. 系统在事务中锁定课程及相关任务；若存在 `PROCESSING` 或 `RETRYING` 任务，返回 409 并回滚事务，不取消其他任务、不改变课程状态，用户待任务进入终态后重试。
3. 不存在执行中任务时，在同一事务中 CAS 取消 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 任务，并将课程及资料标记为逻辑删除，停止新的解析和检索。
4. 首版不提供回收站；管理员清理任务可以删除对应 MinIO 对象、Qdrant 向量和 Lucene document。
5. 删除流程不作为生产级合规清除承诺。

成功解析的单份资料禁止删除。待投递、投递失败、排队、失败、取消的资料可单独删除；排队资料须先取消，处理中/重试中暂不可删除。尝试删除成功资料时返回业务错误并提示“请删除整门课程”。

删除失败或取消的单份资料时，还必须幂等清理该资料的 MinIO 最终原文件、归一化预览和中间对象，以及可能已产生的 CourseSegment、Qdrant point 和 Lucene document；Lucene 删除同样使用课程级索引锁。数据库记录的保留/删除必须与内容哈希唯一约束配套，保证用户之后可以重新上传同一文件。

本文中的数量、大小、TTL、限流、TopK、RRF、超时、评测案例数和阈值均按首版默认配置执行，不是不可修改的业务规则；界面不得把它们硬编码为永久限制。

## Global Status Vocabulary

- 上传：`INITIATED`、`UPLOADING`、`MERGING`、`COMPLETED`、`FAILED`、`EXPIRED`。
- 解析/提纲任务：`PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED`、`PROCESSING`、`RETRYING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。
- 资料解析 Checkpoint：`UPLOADED`、`CONTENT_EXTRACTED`、`CHUNKED`、`EMBEDDING_COMPLETED`、`COMPLETED`。
- 提纲 Checkpoint：`CONTEXT_RETRIEVED`、`OUTLINE_GENERATED`、`COMPLETED`。
- 计划任务：`PENDING`、`COMPLETED`。

所有状态必须同时显示文字，不能只用颜色。
