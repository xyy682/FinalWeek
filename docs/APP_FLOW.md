## Flow 1 — 登录与创建课程

1. 用户输入邮箱，请求验证码。
2. 系统执行邮箱格式和 Redis 限流校验，通过 Mailpit/SMTP 发送验证码。
3. 用户提交验证码，验证成功后创建 HttpOnly Cookie Session。
4. 用户进入课程列表；空状态显示“创建第一门课程”。
5. 用户输入课程名称并创建课程。
6. 系统返回课程详情，默认进入资料页。

### Failure States

- 验证码错误或过期：提示重新输入或发送，不清空邮箱。
- 请求过于频繁：返回 429 和剩余等待时间。
- Redis 不可用：登录及所有需要认证的后端请求统一返回 HTTP 503；静态落地页和健康检查仍可访问。
- 已有 8 门课程：禁止继续创建，提示删除不用的课程。
- 越权访问课程 ID：返回统一的无权访问/不存在响应，不泄露课程信息。

## Flow 2 — 分片上传资料

1. 用户选择 PDF、PPTX、TXT/MD、MP3 或 MP4，并选择资料类型、填写可选重点说明。
2. 前端校验扩展名和大小，调用初始化接口获取 `uploadId`、分片大小和总分片数。
3. 前端并发上传固定大小分片；每个成功分片先落 MinIO，再记录到 Redis Set。
4. 页面刷新或网络恢复后，前端通过 `uploadId` 查询已完成分片并上传差集。
5. 所有分片成功后，前端主动调用 complete。
6. 后端获取该上传任务的合并锁，检查归属、分片完整性和 completed 标记。
7. 后端按序合并分片，计算完整文件哈希，校验类型并保存最终 MinIO 对象与资料记录。
8. 若同一课程已有相同哈希的资料，返回已有资料并清理本次临时文件。
9. 后端先创建 `PENDING_PUBLISH` 解析任务并执行 RabbitMQ 用户级/全局限流：通过后投递消息，publisher confirm 成功后进入 `QUEUED`；限流、发布或 confirm 失败均条件进入 `PUBLISH_FAILED` 并记录具体错误。限流失败不回滚已成功的上传，接口返回同一资料和任务且不发送消息，用户稍后重新投递。

### Failure States

- 单个分片失败：其他分片保留，只重传失败分片。
- complete 重复调用：返回同一资料和任务，不重复合并。
- 两个 complete 并发：只有获取锁的请求执行，另一请求等待或返回处理中。
- 上传元数据过期：提示重新初始化；定时任务清理过期 Redis 状态和 MinIO 临时分片。
- 文件损坏、伪造类型或超限：拒绝创建解析任务，显示具体原因。
- 已解析成功资料：首版不显示单独删除操作；用户只能删除整门课程。待投递、投递失败、排队、失败或已取消资料可删除；排队资料先原子取消。处理中/重试中资料暂不可删除。

## Flow 3 — RabbitMQ 异步解析

1. Spring Boot 在 MySQL 写入 `PENDING_PUBLISH` 任务后投递 RabbitMQ。
2. publisher confirm 成功时任务变为 `QUEUED`；失败时变为 `PUBLISH_FAILED`。接口返回 202 和 `taskId`，不等待解析完成。
3. 消费者收到消息后，以消息 ID 作为 `processing_owner`，通过 MySQL CAS 将待处理状态推进为 `PROCESSING` 并同时写入执行租约。CAS 决定唯一执行者，不再叠加 Redisson 任务锁；confirm 回调不得把后续状态倒退为 `QUEUED`。
4. 若任务已成功，直接确认消息；若未完成，从最近成功 checkpoint 继续。
5. 消费者依次推进：内容提取 → 分块 → Embedding → 索引 → 完成。
6. 每完成一个阶段就更新 MySQL checkpoint，并通过 Redis/SSE 推送进度。
7. 单次外部调用默认最多 3 次执行（首次 + 2 次重试）；整个任务默认最多 3 次执行（首次消费 + 2 次重投），两类计数分别记录。
8. 达到任务级最大执行次数后写失败任务表/失败队列，状态为 FAILED。
9. 执行期间默认每 30 秒续租，租约为 5 分钟；进程崩溃后扫描器按 owner、执行轮次和过期时间 CAS 回收并重新投递。旧 owner 不能再提交成功、失败或重试状态。

### SSE Recovery

- SSE 只是通知渠道，不是业务真相。
- 断线重连后前端先查询任务状态，再继续订阅。
- 即使中间事件丢失，用户仍能获取 MySQL 中的最终状态。

### User Actions

- `PENDING_PUBLISH`、`QUEUED`：允许取消；`PUBLISH_FAILED`：允许取消或重新投递。重新投递复用同一任务和执行轮次，先限流，再以 CAS 回到 `PENDING_PUBLISH` 后发布；若原消息此时延迟到达并抢占成功，重新投递返回冲突且不再发送第二条消息。
- `PROCESSING` / `RETRYING`：只允许查看阶段和错误摘要。
- `FAILED`：允许手动重试或删除资料。手动重试复用原 `taskId` 和 checkpoint，重置新一轮任务级投递预算并增加手动重试轮次，不新建第二条解析任务。
- `SUCCEEDED`：允许查看解析摘要和开始问答；当所有资料任务进入终态后，可在资料页确认成功资料集合并创建知识版本/提纲任务。

取消、重新投递与消费并发时，以 MySQL compare-and-set 为准：只有未开始任务能改为 `CANCELLED`；消费者启动前必须将 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 或 `RETRYING` 原子改为 `PROCESSING`，拿到已取消任务时直接 ack。confirm 超时后延迟到达的原消息与用户重新投递只能有一方成功推进状态。

## Flow 4 — 不同资料的解析

### PDF / PPTX / TXT

1. 提取原生文字。
2. PDF 扫描页或 PPT 渲染页文字不足时调用 OCR。
3. 保存页码、幻灯片号或段落号。
4. 规范化并生成 `CourseSegment`。

### MP3 / MP4

1. FFmpeg 检查时长与媒体格式。
2. 为整份媒体生成一个 16 kHz 单声道 WAV，通过 `paraformer-realtime-v2` Java SDK 本地文件非流式调用 ASR 并读取句级时间戳；应用层不按固定时长拆分 ASR 会话，也不依赖百炼从公网 URL 回源本地 MinIO。
3. MP4 同时按场景变化和保底间隔抽取关键帧，感知哈希去重后调用 OCR。
4. 将 ASR 和 OCR 按时间范围合并成 `CourseSegment`。
5. ASR 或 OCR 单路部分失败时保留另一条可用内容并显示警告；两路都无有效内容时解析失败。

## Flow 5 — 构建课程知识库

1. 将课程片段按语义边界和最大长度切成 chunk。
2. 保存 chunk 原文、来源定位和课程归属。
3. 调用百炼 Embedding，并写入 Qdrant。
4. Qdrant point 携带用户、课程、资料和片段标识。
5. 全部 chunk 写入 Qdrant；Lucene 写入在课程级 Redisson 锁 `lucene-index:{courseId}` 内，使用确定性 document ID 对本资料 chunk 做增量 bulk upsert 并 commit。完成后标记 `EMBEDDING_COMPLETED`。
6. 资料解析任务随后原子进入 `COMPLETED`、任务/资料状态进入 `SUCCEEDED`，此时资料才进入可检索状态；是否生成提纲不影响资料解析完成。从 MySQL 全量重建 Lucene 仅用于初始化或故障修复。

### Failure States

- 部分 Embedding 调用失败：任务按重试规则执行；仍失败则整个 Embedding 阶段失败，不发布半完成索引。
- Qdrant 重复 upsert：使用确定性 point ID 覆盖同一 chunk，不生成重复记录。
- Qdrant 在资料建索引阶段不可用：资料不会提前标记成功，任务按规则重试并从未完成的 Embedding 阶段继续。对已经成功入库的资料执行检索时，向量分支故障会降级到 Lucene BM25；只有向量与 BM25 两路都失败时，提纲、问答和模拟卷检索才返回暂不可用。

## Flow 6 — 混合检索

1. 用户问题或提纲生成目标进入检索服务。
2. 向量分支：问题 Embedding 后在 Qdrant 中按 `userId + courseId` 过滤并召回 TopK。
3. 关键词分支：从当前课程片段建立/读取轻量 BM25 索引并召回 TopK。
4. 使用 RRF 根据两路排名融合，去重后选择最终上下文；RRF 常数和 TopK 均为可配置首版默认值。
5. 上下文附带原资料位置，交给提纲或问答生成器。

若某一路临时不可用，可使用另一路降级并在日志记录；两路都不可用则明确失败，不让模型脱离课程资料生成资料型回答。

## Flow 7 — 确认知识版本并生成提纲

1. 至少一份资料完成索引且所有资料任务进入终态后，“资料已上传完毕”可用。
2. 服务端锁定课程并重新检查资料状态；存在失败或取消资料时，用户必须明确同意忽略。
3. 服务端快照当前全部成功资料，以资料集合哈希阻止相同集合重复确认，并创建不可变知识版本。
4. 确认成功后自动创建 RabbitMQ 提纲任务；没有新增成功资料时不提供手动重复生成。
5. 系统只检索该知识版本的课程片段，并将学生重点说明、教师强调语句、真题/题库类型作为重要度信号。
6. 大模型返回固定 JSON 树结构；后端校验层级、重要度、来源白名单和资料版本归属。
7. 校验通过后原子发布知识版本与提纲；失败时保留旧知识版本和旧提纲，旧任务不得覆盖较新结果。
8. 用户可把当前提纲知识点的重要度改为高/中/低；该人工调整不跨知识版本继承。
9. 用户点击来源，在资料预览中定位页码、幻灯片、段落或视频时间点。

提纲生成拥有独立 checkpoint：`CONTEXT_RETRIEVED → OUTLINE_GENERATED → COMPLETED`，不写入资料解析 checkpoint。来源跳转时，前端先获取经过权限校验的预览描述和短期 URL；PDF/PPTX 使用规范化 PDF 预览，MP3/MP4 播放器通过 Range 请求加载并设置 `currentTime`。

### Failure States

- JSON 格式错误：只做一次严格结构修复，仍失败则任务失败。
- 知识点没有有效来源：不发布该次结果。
- 新知识版本的提纲生成失败：当前已发布知识版本和提纲保持不变，可按失败任务重试。
- 新知识版本发布时不继承旧版人工重要度调整。

## Flow 8 — 简单每日复习计划

1. 用户进入计划页；没有提纲时引导先生成提纲。
2. 用户填写考试日期、每日可用分钟数、整体掌握程度和目标成绩。
3. 前端携带请求幂等键提交，服务端执行用户级限流并返回 `202 + taskId`；RabbitMQ 后台任务固定当前知识版本，按知识点重要度和剩余日期生成每日任务，进度通过通用任务 REST/SSE 恢复。
4. 任务显示日期、知识点、预计分钟数和完成框。
5. 用户手动勾选完成或撤销。
6. 再次生成时提示会覆盖当前计划；确认后替换。

### Failure States

- 考试日期已过、每日时间为零：表单内阻止提交。
- 生成失败：保留当前计划。
- 模型超时或知识/计划版本竞争：后台任务失败并保留当前计划；客户端读取稳定错误后可基于当前版本重新提交。
- 首版不自动识别逾期、不重排、不提供复杂编辑。

## Flow 9 — 课程文字问答

1. 用户进入课程问答，输入文字问题。
2. 前端提交后立即得到 `202` 的 `PENDING` 消息；系统执行用户级 Redis 限流，并在同一事务创建隐藏后台任务。
3. 后台任务检索当前课程全部成功资料；用户离页不会取消服务端处理。
4. 大模型根据检索上下文生成回答，并返回使用的 segment ID。
5. 后端校验引用属于本用户、本课程且确实被提供给模型。
6. 前端展示回答和来源按钮。
7. 若课程资料不足，可追加明确标记的“通用知识补充”。
8. 问答按课程保存为一条连续历史。

### Failure States

- 触发限流：返回 429 和稍后重试提示，不投递模型请求。
- 没有检索结果：说明资料不足，不伪造来源。
- 模型调用失败：保留用户问题并显示重试按钮。
- 引用校验失败：整条助手回答不保存，按结构错误处理。
- 模型超时：将用户消息标为失败并允许按原消息 ID 重试；答疑仍不做 token 流式输出，在线终态可由任务事件提示。

## Flow 10 — 课程删除

1. 用户确认删除课程。
2. 系统在事务中锁定课程及相关任务；若存在 `PROCESSING` 或 `RETRYING` 任务，返回 409 并回滚事务，不取消其他任务、不改变课程状态，用户待任务进入终态后重试。
3. 不存在执行中任务时，在同一事务中 CAS 取消 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 任务，并将课程及资料标记为逻辑删除，停止新的解析和检索。
4. 首版不提供回收站；管理员清理任务可以删除对应 MinIO 对象、Qdrant 向量和 Lucene document。
5. 删除流程不作为生产级合规清除承诺。

成功解析的单份资料禁止删除。待投递、投递失败、排队、失败、取消的资料可单独删除；排队资料须先取消，处理中/重试中暂不可删除。尝试删除成功资料时返回业务错误并提示“请删除整门课程”。

删除失败或取消的单份资料时，还必须幂等清理该资料的 MinIO 最终原文件、归一化预览和中间对象，以及可能已产生的 CourseSegment、Qdrant point 和 Lucene document；Lucene 删除同样使用课程级索引锁。数据库记录的保留/删除必须与内容哈希唯一约束配套，保证用户之后可以重新上传同一文件。

本文中的数量、大小、TTL、限流、TopK、RRF、超时、评测案例数和阈值均按首版默认配置执行，不是不可修改的业务规则；界面不得把它们硬编码为永久限制。

## Global Status Vocabulary

- 上传：`INITIATED`、`UPLOADING`、`MERGING`、`COMPLETED`、`FAILED`、`EXPIRED`。
- 解析/提纲任务：`PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED`、`PROCESSING`、`RETRYING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。
- 资料解析 Checkpoint：`UPLOADED`、`CONTENT_EXTRACTED`、`CHUNKED`、`EMBEDDING_COMPLETED`、`COMPLETED`。
- 提纲 Checkpoint：`CONTEXT_RETRIEVED`、`OUTLINE_GENERATED`、`COMPLETED`。
- 通用后台任务（资料、提纲、计划、模拟卷、隐藏答疑）：`PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED`、`PROCESSING`、`RETRYING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。
- 答疑消息业务状态：`PENDING`、`SUCCEEDED`、`FAILED`。消息状态与承载处理过程的隐藏后台任务状态不是同一概念。

所有状态必须同时显示文字，不能只用颜色。

## Phase 12–16 扩展流程（已实现）

### 目标页面

| Route | 页面 | 目标职责 |
|---|---|---|
| `/courses/:id/materials` | 课程资料 | 上传与解析资料、确认“资料已上传完毕”、查看知识版本准备状态 |
| `/courses/:id/outline` | 知识提纲 | 查看当前自动生成提纲、来源和重要度；不提供无新增资料的重新生成 |
| `/courses/:id/plan` | 复习计划 | 异步生成唯一当前计划、查看版本提示、勾选完成 |
| `/courses/:id/chat` | 课程问答 | 基于全部成功资料提交问题、离页等待、查看连续历史 |
| `/courses/:id/mock-exams` | 模拟卷 | 同页填写出卷表单、分页查看历史、预览下载双 PDF |

五个课程标签始终可见。没有成功资料时答疑页显示引导；没有已发布提纲时计划和模拟卷页不可提交，并引导用户完成资料确认与提纲生成。

### Current Flow 1 — 确认资料并自动生成提纲

1. 用户可以连续上传资料；每份资料仍按现有异步解析流程独立进入知识库。
2. 只要存在上传、待投递、排队、处理或重试中的资料，“资料已上传完毕”按钮就保持禁用并说明原因。
3. 所有进行中资料进入终态后，用户点击确认。没有成功资料时拒绝；存在失败或取消资料时列出将被忽略的资料并二次确认。
4. 服务端在事务中锁定课程，快照当前全部成功资料，创建不可变课程知识版本和异步提纲任务。同一资料集合重复确认返回既有版本或明确冲突，不重复调用模型。
5. 全局任务抽屉显示提纲任务。系统只检索该知识版本的资料，生成并校验带来源提纲。
6. 成功后原子发布知识版本和提纲；旧版停止作为当前版本，但保留供历史计划、模拟卷和生成中任务引用。
7. 失败时保留旧版；首次失败则计划和模拟卷仍未解锁。用户可按原知识版本直接重试，不必再次确认资料。
8. 用户补充资料后重复上述确认流程。没有新增成功资料时不提供手动重新生成。

人工重要度仍可在当前提纲中修改；新知识版本发布时重新生成重要度，不匹配或继承旧版人工调整。

### Current Flow 2 — 跨页面后台任务

1. 所有登录后页面的顶部任务图标显示当前用户活动任务数量。
2. 抽屉只列资料解析、提纲、复习计划和模拟卷的活动任务，展示课程、任务类型、文字状态、关键阶段和进度。
3. 点击任务项跳回相应课程功能页；关闭抽屉或切换课程不会停止任务。
4. 在线完成或失败时通过 SSE 弹出即时提示并移除活动项；SSE 断线后通过活动任务 REST 查询恢复。
5. 排队任务允许取消；消费者已将任务 CAS 为处理中后取消返回冲突。处理、重试和文件生成中的任务不可取消。
6. 终态不保留在抽屉中，业务页面从 MySQL 恢复历史结果；离线期间完成的任务下次登录不补发通知。

### Current Flow 3 — 异步复习计划

1. 没有当前提纲时计划页只显示引导；有提纲时继续使用现有考试日期、每日分钟数、掌握程度和目标成绩表单。
2. 提交后创建计划生成请求和后台任务，返回 `202 + taskId`；全局抽屉显示进度，用户可以离页。
3. 任务固定读取提交时的提纲上下文，但发布前继续执行当前计划版本与提纲版本 CAS。
4. 提纲在生成期间变化、当前计划被较新请求替换或输出校验失败时，任务失败且不覆盖旧计划。
5. 成功后原子替换唯一当前计划。当前计划基于旧知识版本时显示提示，但仍允许完成或撤销任务。
6. 相同幂等键和相同参数重放返回同一请求/结果，不创建重复任务；参数不同返回冲突。

### Current Flow 4 — 可离页课程答疑

1. 任一资料解析成功后即可提交文字问题；检索范围始终是当前全部成功资料，不等待资料确认或提纲发布。
2. 服务端先保存 `PENDING` 用户消息并异步处理，接口返回已受理状态；用户可以切换页面或课程。
3. 答疑工作不显示在全局任务抽屉。在线完成或失败时发送轻量通知；离线时不补发。
4. 回到课程问答页后，历史接口恢复 `PENDING`、`SUCCEEDED` 或 `FAILED` 状态；成功答案仍执行现有引用白名单校验，失败按原消息 ID 重试。
5. 离开页面、关闭浏览器或客户端取消等待不得取消已经受理的服务端回答。

### Current Flow 5 — 创建模拟卷

1. 用户进入模拟卷页。没有已发布知识版本时表单禁用；有未确认新增资料时提示本次只使用当前提纲对应的已确认资料。
2. 用户选择整课或勾选提纲节点。父节点自动选中子树，也可展开后仅选部分子节点。
3. 用户选择一至多种题型并逐题型填写题数；总题数必须为 1–50。总分、1–300 分钟建议时长和最多 2000 字补充说明可选。
4. 用户选择自动分值或按题型自定义单题整数分值；汇总不得超过 1000，填写总分时必须完全一致。
5. “必要时允许模型通用知识补题”默认开启；关闭后，资料不足会使整套生成失败而不是减少题量或静默补题。
6. 前端提交后服务端锁定当前知识版本和提纲范围，创建模拟卷记录与后台任务，返回 `202 + taskId`。同一课程已有活动出卷任务时返回该任务/冲突，不创建第二套。
7. 任务推进：分析要求与资料 → 生成试题 → 校验试卷 → 生成两个 PDF → 完成。用户可自由离开页面。
8. 生成期间发布新版提纲不影响本任务；任务继续使用提交时快照，完成后记录旧版本标识。

### Current Flow 6 — 出题、校验与原子发布

1. 系统先应用结构化字段，再解析不冲突的补充说明；无法兼容的文字要求直接失败并提示修改。
2. 上下文优先使用选定范围的课程片段、人工重要度、教师强调和考试范围；真题由资料类型与内容结构共同识别，例题仅从内容自动识别。
3. 用户要求优先，其次仿照真题，再参考教师例题。只生成新题，不复制或轻微改写原题。
4. 系统按重要度和考试信号分配题量。题数不足以覆盖全部知识点时重点优先并记录警告。
5. 课程资料不足且允许补题时，仅使用模型内置知识补足缺口；不联网。禁止补题时整套失败并列出缺口。
6. 结构化校验必须覆盖题型、题数、选项、答案、分值、范围、内部来源、通用知识标识、公式安全和历史近似题。
7. 课程内题目必须引用本任务允许的 segment；来源只保存在系统内部。历史近似题和范围未完全覆盖是警告，不是硬失败。
8. 使用受控 XeLaTeX 模板分别生成 A4 试卷和参考答案。任一编译、打开、页数或对象存储写入失败时不发布任何文件。
9. 两个对象均保存并复核后，数据库事务原子写入文件信息并把记录改为成功；在线用户收到完成提示。

### Current Flow 7 — 模拟卷历史、预览、重试与删除

1. 历史按创建时间倒序分页，默认显示名称、状态、生成时间和操作。错误或警告记录提供就地展开详情。
2. 成功记录分别获取短时授权的试卷/参考答案预览地址，在新标签页打开；下载使用带生成时间和类型的安全文件名。
3. 失败或取消记录保留原始参数。用户点击重试时回填表单，修改后创建新记录并关联原记录，不覆盖旧快照。
4. 只有排队记录可先取消；运行中记录不可删除。终态记录二次确认后逻辑删除并立即从列表消失。
5. PDF 对象进入不可见的后台清理与失败重试，不出现在全局任务抽屉。课程删除时所有模拟卷和 PDF 一并纳入跨存储清理。

### 目标状态词汇

- 通用后台任务：`PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED`、`PROCESSING`、`RETRYING`、`SUCCEEDED`、`FAILED`、`CANCELLED`。
- 知识版本：`GENERATING`、`PUBLISHED`、`SUPERSEDED`、`FAILED`；一门课程同时只有一个 `PUBLISHED` 当前版本，旧版发布成功后转为 `SUPERSEDED` 并保留内部引用。
- 模拟卷记录：`QUEUED`、`GENERATING`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`DELETED`；展示状态由后台任务和逻辑删除状态确定。
- 模拟卷阶段：`REQUIREMENTS_ANALYZED`、`QUESTIONS_GENERATED`、`PAPER_VALIDATED`、`PDFS_GENERATED`、`COMPLETED`。
- 答疑消息继续使用 `PENDING`、`SUCCEEDED`、`FAILED`，但处理过程不进入全局任务抽屉。

所有状态必须显示中文文字，颜色只能作为辅助信息。
