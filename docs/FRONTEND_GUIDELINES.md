# Frontend Guidelines — FinalWeek（求职版 MVP）

## Visual Direction

- 专注、清爽的浅色学习工具。
- 重点展示课程、资料状态、提纲和下一步操作，不堆插画或复杂动画。
- 桌面 Chrome/Edge 是首要演示环境；手机端保证基本浏览和操作。
- 前端用于完整展示后端链路，但不是本项目的主要技术卖点。

## Design Tokens

### Colors

| Token | Value | Usage |
|---|---:|---|
| `primary` | `#2563EB` | 主按钮、选中项、链接 |
| `primary-hover` | `#1D4ED8` | 主操作悬停 |
| `text` | `#111827` | 标题和正文 |
| `text-secondary` | `#4B5563` | 次要说明 |
| `border` | `#E5E7EB` | 边框和分隔线 |
| `background` | `#F8FAFC` | 页面背景 |
| `surface` | `#FFFFFF` | 卡片和弹窗 |
| `success` | `#15803D` | 成功、已完成 |
| `warning` | `#A16207` | 重试、解析警告 |
| `danger` | `#B91C1C` | 失败、删除 |

状态和重要度必须显示文字，不能只依赖颜色。

### Spacing and Shape

- 间距：4 / 8 / 12 / 16 / 24 / 32 / 48px。
- 控件圆角：8px；卡片和弹窗：12px。
- 页面内容最大宽度：1280px。
- 手机页面水平内边距：16px；桌面：24–32px。
- 普通卡片使用 1px 边框，不叠加重阴影。

### Typography

- 字体：`Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`。
- 正文：14px/22px。
- 页面标题：28px/36px，600。
- 区块标题：20px/28px，600。
- 卡片标题：16px/24px，600。

## Responsive Rules

- `mobile`: `<768px`。
- `desktop`: `≥768px`。
- 桌面资料列表使用表格；手机改为卡片列表。
- 课程四个区域在手机使用横向可滚动标签。
- 树状提纲在手机保持折叠、来源查看和重要度调整。
- 首版不为 Safari/Firefox 建立正式测试矩阵，但不使用 Chromium 私有 API。

## Main Screens

### Login

- 单列邮箱和验证码表单。
- 显示验证码发送倒计时和 Mailpit 开发提示。
- 错误显示在对应字段下，提交失败不清空邮箱。
- Redis 不可用时明确显示“服务暂时不可用（503）”，不将其误报为验证码错误。

### Course List

- 空状态只有一个主操作“创建课程”。
- 课程卡片显示课程名、资料数量、最近解析状态和更新时间。
- 支持重命名和删除；删除使用确认弹窗。
- 删除时若课程仍有解析中/重试中任务，展示后端 409 提示并保留课程，待任务进入终态后允许再次删除。

### Course Navigation

- 课程标题下固定四个标签：资料、知识提纲、复习计划、课程问答。
- 每个标签有独立 URL，刷新后保留当前页面。
- 顶部显示正在执行的任务及当前阶段。

## Core Components

### Upload Panel

- 支持拖拽和文件选择。
- 显示文件名、大小、资料类型、重点说明、分片进度和操作。
- 上传中断后显示“继续上传”，并从后端读取已完成分片。
- 上传完成后切换为解析进度，显示阶段和百分比。
- `PENDING_PUBLISH` 显示“待投递”，`PUBLISH_FAILED` 显示“投递失败”及安全错误摘要并提供“重新投递”；若原因为 `AI_RATE_LIMITED`，明确提示稍后再试。解析失败显示“重试/删除”。
- 解析失败后的“重试”复用原任务和进度卡；前端不得创建第二张并行任务卡，手动重试轮次可作为辅助信息展示。
- 已解析成功的资料不显示单独删除入口；待投递、投递失败、排队、失败或已取消资料可按后端规则删除，排队资料由后端先原子取消。处理中/重试中暂不显示删除入口。成功资料只随整门课程删除。
- 不把上传进度和解析进度合并成一条含义不清的进度条。

### Task Status

- 状态文案：待投递、投递失败、排队中、解析中、重试中、解析成功、解析失败、已取消。
- 长任务使用持久任务卡，不只使用 toast 或无限转圈。
- SSE 断线时显示“正在重新连接”，同时保留最后状态。
- 失败卡片显示错误阶段、错误摘要和请求 ID。

### Outline Tree

- 默认展开前两层。
- 节点展示名称、重要度和来源数量。
- 重要度通过下拉选择高/中/低，修改后立即保存。
- 点击来源打开侧栏：文件名、页码/幻灯片/段落/时间点和原文片段。
- PDF/PPTX 来源通过后端预览接口打开归一化 PDF 并定位页码；MP3/MP4 来源按时间点设置播放器 `currentTime`，播放请求支持 Range。预览 URL 过期时重新请求，不缓存为永久链接。
- 首版不提供拖拽、增删节点、重命名或结构合并。
- 再次生成时弹窗明确说明“将覆盖当前提纲及人工重要度调整”。
- 本课程已有活动提纲任务时禁用重复生成并继续展示该任务进度；刷新后从后端恢复现有活动任务。

### Study Plan

- 表单字段：考试日期、每日可用分钟数、整体掌握程度、目标成绩。
- 结果按日期分组展示任务。
- 每项包含知识点、预计用时和完成复选框。
- 只提供完成/撤销完成；不提供拖拽、跳过、重排和差异预览。
- 再次生成前提示覆盖。
- 生成操作使用同步 REST：每次用户确认生成时创建请求幂等键，提交期间禁用重复提交；请求超时时先重新获取当前计划，再以同一幂等键重试，不能假定服务端一定未成功。
- 计划生成触发 429 时显示稍后重试，不自动更换幂等键或无限重试。

### Course Chat

- 每门课程一条连续历史。
- 输入仅支持文字。
- 回答结构固定为：回答正文、课程资料来源、通用知识补充（可选）。
- 引用按钮显示文件名和位置，点击打开预览。
- 发送失败保留用户问题并允许重试。
- 问答使用非流式同步 REST；等待期间显示可取消的本地加载态，请求超时后保留输入并刷新历史，避免重复消息。
- 不提供会话列表、图片输入和复杂长期记忆设置。

## Forms and Feedback

- 所有字段有可见标签；必填项有明确标识。
- 客户端校验用于即时反馈，服务端仍需重复校验。
- 提交中禁止重复提交，但不清空输入。
- 删除、覆盖提纲、覆盖计划必须二次确认。
- 429 显示“请求过于频繁，请稍后再试”，不得自动无限重试。
- 任一已认证接口返回 503 时显示全局“服务暂时不可用”，停止自动重试；静态落地页仍可浏览。
- 错误响应展示稳定错误码或请求 ID，方便面试演示日志排查。

## Basic Accessibility

- 按钮、输入框和链接可用键盘访问。
- 焦点样式可见。
- 图标按钮有文字标签或 `aria-label`。
- 表单错误与字段关联。
- 文字和背景保持基本可读对比度。
- 首版不以正式 WCAG 2.2 AA 审计作为完成条件。

## Component Rules

- 业务组件使用 PascalCase，例如 `MaterialUploadPanel`、`TaskStatusCard`、`OutlineTree`。
- 使用 Element Plus 和统一设计令牌，不引入第二套 UI 库。
- 组件通过 typed props/emits 与 API service 交互，不直接拼接任意后端地址。
- API 类型集中管理；不得使用大面积 `any`。
- Markdown 必须清洗，不渲染模型返回的原始 HTML。

## Do

- 把任务阶段、失败原因和恢复操作展示清楚。
- 把来源定位作为提纲和问答的核心界面元素。
- 为覆盖和删除操作提供明确确认。
- 在桌面演示环境优先保证流程顺畅。

## Don't

- 不加入深色模式、复杂动画、思维导图或游戏化系统。
- 不在手机端复制复杂桌面表格。
- 不把通用知识伪装成课程资料。
- 不静默覆盖提纲或计划。
- 不为求职演示引入复杂前端架构。
