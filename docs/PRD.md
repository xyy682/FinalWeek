# PRD — FinalWeek（求职版 MVP）

## Product Goal

FinalWeek 是面向大学生期末复习的课程资料理解工具。学生创建课程并上传 PDF、PPTX、音频或视频后，系统异步执行文本提取、ASR、OCR、分块与索引，生成带原资料位置的知识提纲，并支持简单每日复习计划和基于课程资料的文字问答。

首版目标不是建设生产级 SaaS，而是完成一个可本地运行、可演示、可测试、面试中能够深入解释的 Java 后端求职项目。

核心链路：

```text
登录 → 创建课程 → 分片上传资料 → RabbitMQ 异步解析
→ ASR/OCR 与文本提取 → 课程知识库 → 带来源提纲
→ 简单复习计划 / 课程文字问答
```

## Target Users

- 独立复习个人课程的在校大学生。
- 主要使用中文资料，也支持中英混排内容。
- 首版只提供简体中文界面。
- 每个用户只能访问自己的课程、资料、任务和结果。

## Core Problems

1. 课程资料分散在 PDF、PPT 和录课音视频中，学生难以快速形成知识结构。
2. 大文件上传与 ASR/OCR/AI 调用耗时长，普通同步请求不可靠。
3. AI 总结容易缺少依据，学生无法回到原资料核验。
4. 长资料直接塞给大模型噪声大、成本高，需要检索后按需加载。

## In Scope — 必须完成

### 1. 登录与课程

- 邮箱验证码登录；本地开发使用 Mailpit 接收验证码。
- 使用 HttpOnly Cookie 保存登录会话，Redis 保存服务端 Session。
- 创建、查看、重命名和逻辑删除课程。
- 删除课程时在同一事务中锁定课程及相关任务：若存在处理中/重试中任务，则返回 409 且不改变任何任务；否则原子取消待投递、投递失败和排队任务并逻辑删除课程。首版不引入执行中任务的协作式取消。
- 每个账号最多 8 门未删除课程。
- 课程页面包含资料、知识提纲、复习计划、课程问答四个区域。

### 2. 资料上传

- 支持格式：PDF、PPTX、TXT/MD、MP3、MP4。
- 单个文档不超过 100MB；单个音视频不超过 2GB 且不超过 2 小时。
- 大文件按固定大小分片上传；Redis 记录上传任务和已完成分片，MinIO 保存临时分片和最终文件。
- 网络中断后查询已上传分片，只补传缺失部分。
- 合并接口必须校验分片完整性、文件归属和文件类型，并保证重复调用不会生成重复文件记录。
- 上传时选择资料类型：课件、笔记、真题、题库、录音、视频、其他；可填写老师强调内容或考试范围。
- 同一课程内容哈希重复时拒绝重复解析并返回已有资料。
- 状态为待投递、投递失败、排队、失败或已取消的资料可以单独删除；排队资料先以 CAS 取消任务。处理中/重试中的资料暂不可删除，待任务进入终态后再按状态处理。一旦资料解析成功，首版禁止单独删除，只能通过删除整门课程统一清理，避免提纲、计划和问答引用失效。

### 3. RabbitMQ 异步解析

- 上传完成后先创建 `PENDING_PUBLISH` 解析任务，再投递 RabbitMQ；publisher confirm 成功后进入 `QUEUED`。投递失败进入 `PUBLISH_FAILED`，用户可重新投递，不能留下实际无消息的“假排队”任务。
- 消费者可能早于 publisher confirm 回调收到消息，confirm 超时后消息也可能延迟到达；合法消息到达本身可证明已投递，因此消费者允许以 CAS 将 `PENDING_PUBLISH`、`PUBLISH_FAILED`、`QUEUED` 或 `RETRYING` 推进到 `PROCESSING`，confirm 回调只能条件更新且不得倒退更靠后的状态。
- Spring Boot 内置消费者执行解析，不建立独立 Python Worker。
- MySQL 保存任务最终状态，Redis 保存实时进度，SSE 向前端推送阶段变化。
- 任务状态：待投递、投递失败、排队、处理中、重试中、成功、失败、已取消。
- 排队任务可取消；执行中的任务不可取消。
- 外部 API 每次调用默认最多执行 3 次（首次 + 2 次重试）；RabbitMQ 任务默认最多执行 3 次（首次消费 + 2 次重投）。两层次数分别记录，参数、鉴权、文件损坏等永久错误不进入任何重试。
- 任务级重投仍失败后写入失败任务表和失败队列，允许手动重新投递。
- 普通用户手动重试失败资料时复用原 `taskId`、既有 checkpoint 和 business key，开启新一轮任务级投递预算并增加 `manualRetryCount`；不得创建第二条资料解析任务。旧失败记录相应转为已重投，最终成功后转为已解决。

### 4. 课程内容解析

- PDF：提取正文并保留页码；扫描页调用 OCR。
- PPTX：提取文本并保留幻灯片号；必要时转换/渲染后 OCR。
- TXT/MD：按段落提取。
- MP3/MP4：FFmpeg 提取和切分音频，使用支持 Java 本地文件/音频流输入的百炼实时识别接口，首版默认 `paraformer-realtime-v2`，ASR 返回带时间戳转写；不得要求本地 MinIO 暴露公网 URL。
- MP4：按场景变化和固定时间间隔抽取关键帧，OCR 识别字幕、课件文字和清晰板书。
- ASR 与 OCR 结果按时间轴合并为课程片段。
- 不承诺识别潦草手写、复杂图表、复杂公式或纯视觉动作。

统一片段至少包含：

- `materialId`
- `content`
- `sourceType`
- `pageNumber` / `slideNumber` / `paragraphNumber`
- `startTimeMs` / `endTimeMs`
- `asrText` / `ocrText`

### 5. 阶段级 Checkpoint

解析任务只实现阶段级恢复，不建设通用分块恢复框架。

资料解析任务阶段：

```text
UPLOADED
→ CONTENT_EXTRACTED
→ CHUNKED
→ EMBEDDING_COMPLETED
→ COMPLETED
```

提纲生成是用户主动发起的独立任务，不属于资料解析必经阶段：

```text
QUEUED
→ CONTEXT_RETRIEVED
→ OUTLINE_GENERATED
→ COMPLETED
```

- 每完成一个阶段，将结果位置和阶段状态写入 MySQL。
- RabbitMQ 重投或手动重试时，从最近成功阶段继续。
- 同一任务的重复消息不能产生重复片段、向量、提纲或数据库记录。
- 同一课程的 Lucene 正常写入必须在课程级 Redisson 锁 `lucene-index:{courseId}` 内，使用确定性 document ID 对本资料全部 chunk 做增量 bulk upsert 并 commit 后释放锁；从 MySQL 全量重建只用于初始化或故障修复，不是单份资料解析的必经步骤。
- 如果模型或解析配置变化，可由管理员手动触发整份资料重新解析；首版不做自动 checkpoint 失效传播。

### 6. 课程知识库与混合检索

- 课程片段按语义边界和固定上限切块，并保留来源定位。
- 使用百炼 Embedding 生成向量并写入 Qdrant。
- 所有向量必须带 `userId`、`courseId`、`materialId`、`segmentId`，检索时强制按用户和课程过滤。
- 课程问答同时执行：
  - Qdrant 向量召回；
  - Java 侧关键词/BM25 召回。
- 使用 RRF 合并两路排名，选取 TopK 课程片段提供给大模型。
- 首版不加入 Cross-Encoder 重排、查询改写、多模型路由或联网搜索。

### 7. 带来源的知识提纲

- 至少一份资料解析成功后，用户手动生成提纲。
- 提纲生成使用 RabbitMQ 异步任务和任务 SSE；资料解析完成不依赖是否生成提纲。
- 每个知识点包含：名称、父子层级、高/中/低重要度和至少一个来源。
- 来源可定位到 PDF 页码、PPT 幻灯片、文本段落或音视频时间点。
- 重要度优先参考学生填写的重点说明、教师强调语句和真题/题库出现情况，再参考标题、重复和篇幅。
- 提纲以可折叠树状列表展示。
- 学生可以人工调整知识点的重要度。
- 首版不允许修改树结构，不实现人工修改与重新生成的智能合并。
- 重新生成前明确提示将覆盖当前提纲，用户确认后才执行。
- 同一课程同一时刻最多允许一个活动提纲生成任务；重复或并发请求返回已有活动任务，不得让旧任务覆盖较新的生成结果。
- 只保留当前提纲，不保存版本历史。

### 8. 简单每日复习计划

- 计划基于当前知识提纲生成。
- 用户输入考试日期、每天可用分钟数、整体掌握程度和目标成绩。
- 系统结合重要度生成按日期排列的每日知识点任务。
- 计划生成使用同步 REST，请求默认超时为可配置值；不进入 RabbitMQ，也不通过任务 SSE 推送。
- 计划生成使用客户端请求幂等键和服务端唯一当前计划约束；超时后先读取当前计划，使用同一幂等键重试，不能生成多份“当前计划”。
- 任务包含知识点、预计用时和状态：待完成、已完成。
- 学生手动勾选或撤销完成。
- 只保留当前计划；重新生成前提示覆盖。
- 不实现逾期自动重排、差异预览、拖动日期、跳过状态或复杂日历。

### 9. 课程文字问答

- 至少一份资料索引成功后可开始问答。
- 首版只接受文字问题，不接受聊天图片或其他附件。
- 问答使用非流式同步 REST，请求默认超时为可配置值；首版不提供聊天流式 SSE。
- 每门课程保存一条连续聊天历史。
- 回答优先基于混合检索得到的课程片段，并给出可点击来源。
- 课程资料不足时明确说明；允许补充模型通用知识，但必须单独标记“通用知识补充”。
- 不允许跨课程检索，不使用联网搜索。

### 10. Redis 限流与成本保护

- 在 RabbitMQ 投递、同步计划生成和课程问答调用前执行 Redis 令牌桶限流。RabbitMQ 限流同时覆盖资料解析与提纲生成。
- 上传 complete 已成功创建资料和任务但 RabbitMQ 限流未通过时，不回滚上传结果；任务条件转为 `PUBLISH_FAILED` 并记录 `AI_RATE_LIMITED`，不发送消息，用户稍后从同一任务重新投递。提纲生成限流未通过时直接返回 429，不创建任务。
- 首版初始默认值：RabbitMQ 任务单用户每分钟 5 次、全局每分钟 30 次；计划生成单用户每分钟 5 次；问答单用户每分钟 20 条。
- 上述值均为可配置的本地 MVP 默认值，不属于不可修改的业务需求，也不宣称为生产最优值。
- Redis 同时承载登录 Session、验证码、锁和限流。Redis 不可用时，登录及所有需要认证的后端请求暂时不可用，统一返回 HTTP 503；静态落地页和健康检查仍可访问。
- 首版不实现按月 Token 配额、付费套餐、额度预留或配额账本。

### 11. 简单 AI 评测集

- 首版默认建立至少 8 个可重复运行的 Golden Case，覆盖：原生 PDF、扫描 PDF、PPTX、纯音频、音视频互补、真题重点、课程问答有答案、课程问答无答案。
- 对提纲评估知识点覆盖率、来源定位正确率、重要度一致率。
- 对问答评估课程资料忠实度、答案相关性和引用正确率。
- 初始评测目标：核心知识点覆盖率 ≥80%，来源/引用正确率 ≥90%，未标记的无依据陈述比例 ≤10%。案例数量和阈值均为可配置首版默认值，可根据首次实测调整；调整时必须同步更新规范和报告。
- README 必须写实际运行结果；未运行前只能写目标，不能包装成已达到指标。

### 12. Docker 本地运行

- Docker Compose 默认一键启动 Vue、Spring Boot、MySQL、Redis、RabbitMQ、MinIO、Qdrant 和 Mailpit，形成可直接演示的完整应用。
- 开发模式允许只启动中间件，再在本机运行 Vue 与 Spring Boot；这不替代完整 Compose 的交付要求。
- 提供 `.env.example`、健康检查、启动说明和演示流程。

## Configuration Policy

首版出现的数量、大小、时长、TTL、限流、TopK、RRF 常数、同步超时、历史消息条数、评测案例数和验收阈值，均是“首版默认可配置值”，用于给实现与演示提供一致基线，不视为不可修改业务需求。调整时必须修改集中配置、示例环境文件、相关自动化测试；AI 评测值还必须写入当次报告配置快照。

## Out of Scope — 明确不做

- 教师、班级、多人协作、分享和公开链接。
- Word、独立图片上传及更多音视频容器格式。
- Python Worker、微服务和 Kubernetes。
- 通用阶段+分块 checkpoint 引擎。
- 提纲结构编辑、智能合并和冲突解决系统。
- 计划逾期重排、差异预览和复杂任务编辑。
- 聊天图片、多会话管理和长期记忆优化。
- 月度配额账本、付费、订单和套餐。
- 14 天回收站、跨存储立即清除和生产级数据生命周期。
- 成功解析资料的单独删除；首版只允许删除未成功资料或整门课程。
- Cross-Encoder 重排、Query Rewrite、多模型路由、Planner–Executor–Critic Agent。
- Prometheus、Grafana、分布式追踪、自动备份和生产告警。
- 正式 WCAG 2.2 AA 验收和完整浏览器兼容矩阵。
- 公网部署、真实生产 SLA 和大规模高并发。

## User Stories

- 作为学生，我希望稳定上传课程资料，即使网络中断也不用从头上传。
- 作为学生，我希望看到解析阶段和失败原因，而不是一直等待同步请求。
- 作为学生，我希望提纲中的知识点能回到原资料核验。
- 作为学生，我希望系统结合重点和真题标记知识点重要度，并允许我人工纠正。
- 作为学生，我希望根据考试日期生成简单的每日复习任务。
- 作为学生，我希望围绕课程资料提问，并区分资料依据和模型通用知识。

## Success Criteria

### 功能

- 完整跑通登录、建课、分片上传、异步解析、提纲、计划和问答。
- 支持 PDF、PPTX、TXT/MD、MP3、MP4 的正常与失败流程。
- RabbitMQ 重投后能利用阶段 checkpoint 恢复，且不产生重复结果。
- SSE 断开后重新连接仍能获取最终任务状态。

### AI

- 按当前配置的 Golden Case 数量实际运行并保存输入、标注、输出、评分、模型 ID 与配置；首版默认至少 8 个。
- 达到本文设定的覆盖、引用和无依据陈述目标；未达到时如实记录结果与分析。

### 工程

- Docker Compose 能在干净环境一键启动前端、后端和全部依赖。
- 核心单元测试、容器集成测试和一条关键 E2E 主流程通过。
- 对重复上传、重复消费、第三方超时、Redis 暂时不可用和 SSE 重连有可复现测试。
- README 包含架构图、截图、运行命令、实际测试数据、已知不足和面试可讲的技术取舍。
