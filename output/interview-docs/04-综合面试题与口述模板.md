# FinalWeek 综合面试题与口述模板

## 1. 30 秒项目介绍

> FinalWeek 是一个面向大学生期末复习的多模态课程资料 RAG 系统。它支持 PDF、PPT、文本和音视频上传，通过 PDFBox、POI、FFmpeg、OCR 和 ASR 统一解析成带页码或时间戳的 CourseSegment，再写入 Qdrant 和 Lucene，通过 RRF 做混合检索。在知识库之上实现了提纲、计划、问答和模拟卷。耗时任务统一用 RabbitMQ 异步执行，并通过 MySQL 状态机、CAS、checkpoint 和幂等写支持失败恢复。

## 2. 90 秒项目介绍

> 我做 FinalWeek 是因为期末资料通常散落在课件、PDF、录音和视频里，直接调用聊天模型既无法稳定处理多格式，也很难约束回答只依据课程内容。
>
> 主链路是先分片上传资料到 MinIO，然后通过 RabbitMQ 异步解析。PDF 和 PPT 保留页级定位，音视频通过 ASR、抽帧 OCR 和时间线合并保留时间戳，最后统一成 CourseSegment。每个 segment 同时写入 Qdrant 向量索引和 Lucene BM25 索引，查询时用 RRF 融合，再回查 MySQL 做权限和成功状态过滤。
>
> 在这个知识底座上，我实现了版本化提纲、异步复习计划、带引用的课程问答，以及经过 JSON Schema 和 Java 业务校验的模拟卷。模拟卷从同一份 DTO 用 XeLaTeX 生成试卷和答案两份 PDF。工程上我重点处理了重复上传、重复消息、模型输出非法和跨存储部分失败，通过唯一约束、CAS、checkpoint、稳定 ID 和补偿清理让失败可见并可恢复。

## 3. 五分钟讲解提纲

按下面顺序讲，不要逐个报技术栈：

1. 场景痛点：资料多格式、模型不可信、长任务、结果要追溯。
2. 知识入库：分片上传 -> 解析 -> CourseSegment -> 双索引。
3. RAG：Qdrant + BM25 -> RRF -> MySQL 回查。
4. AI 工作流：提纲、计划、问答、模拟卷如何共用知识底座。
5. 可靠性：任务状态机、CAS、checkpoint、幂等与补偿。
6. 边界：单实例模块化单体、无生产 SLA、无 Cross-Encoder。

## 4. 架构总问题

### Q1：项目里最难的部分是什么？

推荐回答：

> 最难的不是接模型 API，而是让多个长耗时、可能重复执行的工作流共享同一套可靠的知识数据。比如上传完成、MQ 投递、解析 checkpoint、两种索引和资料成功状态之间不能简单放进一个事务。我把 MySQL 作为真相源，通过明确状态机、稳定 ID、幂等 upsert 和补偿来处理跨系统间隙；上层再通过知识版本解决异步生成读到不同资料集合的问题。

### Q2：如果让你删掉一个中间件，会删什么？

> 对当前求职 MVP，我会优先评估删掉 Qdrant 或 RabbitMQ 的必要性，但要看目标。若只做小资料 Demo，可以用数据库向量扩展或同步任务减少组件；若保留多模态解析和离页执行，RabbitMQ 的价值更高。Lucene 也可以换成数据库全文检索，但中文分词和课程级索引质量需要重新评估。当前组件较多，是为了展示完整链路，生产落地前会根据规模重新收敛。

### Q3：为什么说是模块化单体，不是微服务？

> 所有业务模块在同一个 Spring Boot 进程和数据库里，调用是进程内方法调用；RabbitMQ Consumer 也在同一 JVM。模块是代码边界，不是独立部署边界。这样更适合当前规模，但不能独立扩缩容。

### Q4：系统的单点和瓶颈在哪里？

- 单后端实例和本地 Lucene；
- OCR/ASR/LLM 外部服务延迟；
- Consumer prefetch 低时的后台吞吐；
- complete 阶段临时磁盘与 MinIO IO；
- 大量课程的 Lucene 本地索引容量；
- MySQL 热点课程行锁和任务状态更新。

### Q5：如果要支持 10 万用户，第一步怎么改？

不要直接说“加机器”。推荐顺序：

1. 先通过指标确认上传、解析、检索和模型调用的实际瓶颈。
2. Web API 与 Worker 分离部署，任务按类型拆队列和并发额度。
3. 将本地 Lucene 换成可横向扩展的搜索服务。
4. 引入 Outbox，增强任务投递完整性。
5. 上传改为客户端直传对象存储并使用短时凭证，降低后端带宽。
6. 加入配额、成本控制、熔断、监控和告警。
7. 对模型上下文、Embedding 和热门查询做有边界的缓存。

## 5. 故障场景题

### Q1：Redis 在上传一半时宕机怎么办？

当前行为：上传临时状态不可用，接口应失败；MinIO 已写分片可能成为临时对象，由 TTL/清理任务回收。因为分片明细未持久化 MySQL，不能保证 Redis 数据丢失后原 uploadId 继续续传。这是当前方案的可接受边界。

### Q2：RabbitMQ confirm 超时，但消息其实已经到队列怎么办？

任务可能暂时被标记 PUBLISH_FAILED，但消费者拿到合法消息后可以用 CAS 推进到 PROCESSING；confirm 回调或重投不能把状态倒退。重复消息由任务状态和轮次检查直接 ack。

### Q3：Embedding 完成了一半，任务失败怎么办？

Qdrant 已存在部分 point，但 Material 未标记 SUCCEEDED，最终检索回查时不会暴露。任务重试使用稳定 segment UUID upsert，覆盖已有 point，完成全部批次后才提交阶段 checkpoint。

### Q4：Qdrant 数据全部丢失怎么办？

MySQL 中仍保存 CourseSegment，因此向量索引属于可重建派生数据。当前项目重点实现 Lucene 启动核对与重建；若生产化，应增加 Qdrant reconciliation 和批量重嵌入流程，同时控制模型成本。

### Q5：旧提纲任务比新任务晚完成怎么办？

发布时校验知识版本和 generationVersion，并通过 CAS 切换当前指针。旧任务即使生成成功，也不能覆盖新版本；其历史记录可保留用于排查。

### Q6：试卷 PDF 上传一份后第二份失败怎么办？

立即尝试删除已上传对象；清理失败写 cleanup 记录并后台重试。数据库不发布两份对象键，用户不会看到半套成功结果。

### Q7：SSE 事件丢失怎么办？

任务状态已经先写入 MySQL。前端刷新或重连时通过 REST 获取活动任务和最终结果，因此事件丢失只影响实时性，不影响终态正确性。

## 6. 数据库与并发题

### Q1：悲观锁、Redis 锁、CAS 和唯一索引各自用在哪？

- 悲观行锁：需要在同一事务内读取并修改课程/业务聚合时。
- Redis 锁：跨线程、跨进程减少重复执行，例如 upload complete 和课程 Lucene 写。
- CAS：任务状态迁移、取消竞争、版本发布。
- 唯一索引：相同 business key、material hash、segment chunk 的最终重复兜底。

### Q2：为什么 Redis 锁之后还需要数据库唯一约束？

锁可能超时、进程暂停、网络分区或误配置；数据库约束与最终写入处于同一系统边界，是防止重复业务记录的最后防线。

### Q3：如何避免慢事务？

模型调用、文件合并、OCR 和 PDF 编译都不放在数据库事务中。事务只包围短的业务状态创建、CAS 和结果发布。跨存储工作通过任务状态与补偿衔接。

### Q4：课程删除为什么复杂？

课程数据分布在 MySQL、MinIO、Qdrant 和 Lucene。项目先在 MySQL 锁定课程与相关任务：执行中的任务阻止删除，未开始任务可 CAS 取消，然后逻辑删除课程。跨存储清理由管理员 reconciliation 处理，而不是在 HTTP 事务里假装原子删除所有系统。

## 7. RAG 与模型题

### Q1：Prompt 里如何降低幻觉？

- 只提供检索后的 segment；
- 明确 sourceSegmentIds 白名单；
- 结构化区分课程回答和通用知识；
- 应用层验证引用属于本次上下文；
- 无检索结果时直接返回资料不足；
- 模型输出无效时不发布。

这些机制能降低和暴露幻觉，不能宣称彻底消除。

### Q2：为什么提纲检索只用一个固定 query？

当前提纲采用“核心知识点、教师强调、真题”等综合查询，是 MVP 的上下文构造策略。它可能遗漏长尾章节。模拟卷已经使用提纲节点多 query 扩展；提纲后续可按资料目录、聚类或 map-reduce 分层生成，避免单次 TopK 代表整门课程。

### Q3：Embedding 维度和批次为什么配置化？

模型维度影响 Qdrant collection 结构，批次受供应商 API 限制且影响吞吐和失败范围。代码限制 batch size 在模型允许范围内，避免配置错误运行到一半才失败。

### Q4：问答为什么不做流式 token？

项目优先保证结构化回答、来源校验和离页恢复。流式 token 在模型输出完整前无法做 JSON 与引用验证，也会增加前端状态复杂度。当前先后台生成完整结果，再通过任务状态通知。

### Q5：如何处理 Prompt Injection？

课程资料被当作不可信上下文，不应允许其中指令覆盖系统约束；输出仍需结构和来源白名单校验。当前项目没有完整的内容安全或 prompt injection 评测，生产化应增加上下文分隔、指令优先级、恶意样本评测和敏感操作隔离。因为系统没有让模型直接调用高权限工具，风险面小于 Agent 系统，但仍不能忽略内容污染。

## 8. 测试与质量题

### Q1：测试金字塔是什么样？

- JUnit：领域规则、状态机、解析器、检索、校验器和并发竞争。
- Testcontainers：MySQL/JPA 等真实基础设施集成行为。
- XeLaTeX 集成测试：中文、公式、模板和双 PDF。
- Vitest：前端工具和页面行为。
- Playwright：桌面、Edge、移动端以及真实主链路。
- Golden Eval：固定多模态输入和 AI 输出指标。

### Q2：哪些最值得做并发测试？

- 两个 complete 同时提交；
- 同课程相同 hash 的不同上传会话；
- 重复 MQ 消息同时消费；
- 确认知识版本的双线程竞争；
- 同课程同时生成计划/模拟卷；
- 任务取消与 Consumer claim 竞争；
- 旧版本发布与新版本创建竞争。

### Q3：为什么单测通过仍可能线上失败？

外部模型非确定、对象存储和 MQ 有网络故障、FFmpeg/LibreOffice/XeLaTeX 有环境依赖，且并发时序组合无法完全枚举。因此还需要集成测试、E2E、Golden Case、结构化日志和生产指标。

## 9. AI Coding 真实性问题

如果面试官问“这个项目是不是 AI 写的”，不要回避，也不要把所有代码归功于自己手写。

可以如实回答：

> 我使用了 Codex/Claude Code 辅助实现，但不是一句 Prompt 生成后直接使用。我负责确定产品范围和架构约束，把功能拆成阶段，要求生成代码必须经过单测、集成测试、浏览器 E2E 和真实模型 Golden Case；我也需要检查并发状态、事务边界、失败补偿和文档是否与实现一致。AI 提升了编码速度，但架构取舍、验收标准和最终结果由我负责。

面试官可能继续问：

### Q1：如果代码不是逐行手写，怎么证明你理解？

回答方式：现场从任意一条请求讲状态变化、表记录、异常路径和替代方案；能够定位核心类并解释测试。不要只背 README。

### Q2：AI 最容易写错什么？

- 把 Redis 锁误当成正确性保证；
- 外部调用放在长事务内；
- confirm 回调把较新状态倒退；
- checkpoint 先于产物提交；
- 重试循环叠加导致模型调用爆炸；
- 只写成功路径，不写跨存储补偿；
- 文档宣称强一致或高可用，但代码没有做到。

### Q3：你实际做了哪些判断？

请根据真实经历选择，不要全部照搬：

- 定义需求范围和不做项；
- 选择模块化单体而非微服务；
- 确定 MySQL 为真相源；
- 设计后台任务状态机和 checkpoint；
- 制定来源白名单和模型输出校验规则；
- 设计测试矩阵和 Golden Case；
- 通过失败注入修正竞态、重试和清理逻辑。

## 10. 反问和改进题

### Q1：如果再做一周，你最想改什么？

推荐选一个深入回答：

- 建立独立检索标注集，测 Recall@K/MRR，并评估 Cross-Encoder；
- 引入 Outbox，收窄数据库与 MQ 的投递窗口；
- 将 Worker 与 API 分离，按任务类型配置并发和成本配额；
- 将本地 Lucene 迁移到 OpenSearch，支持多实例；
- 为模型调用增加熔断、按用户预算和可观测成本指标；
- 改进提纲上下文构造，避免固定 TopK 遗漏长尾章节。

### Q2：你认为当前最值得删除的过度设计是什么？

这是开放题。可以坦诚说组件数量对于个人 MVP 偏多，但它们分别服务于你想展示的上传可靠性、异步任务和混合 RAG。若目标变成快速上线验证需求，可以先用 PostgreSQL + pgvector + 对象存储 + 单后台队列收敛组件，再根据真实瓶颈拆分。
